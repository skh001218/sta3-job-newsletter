# 작성 템플릿

## Notion 상황형 관점 전환 퀴즈

데이터베이스의 각 자료 상세 페이지에 아래 양식을 사용한다. 상황과 선택지만으로 먼저 판단할 수 있게 원문의 결론과 추천 답은 마지막 토글 밖에 노출하지 않는다.

`내 답변`의 안내 문구는 사용자가 직접 지우고 입력하는 영역이다. Notion 페이지에서 편집할 수 있도록 일반 인용문 블록으로 만든다.

```markdown
<callout icon="🧠" color="blue_bg">
	정답을 열기 전에 하나를 고르고, 왜 그렇게 판단했는지 직접 적어보세요.
</callout>

## 상황

[원문의 결론을 미리 알려주지 않는 게임 운영·분석 상황]

## 선택

- **A.** [판단 1]
- **B.** [판단 2]
- **C.** [판단 3]
- **D.** [판단 4]

## 내 답변

### 선택한 답

> [여기를 지우고 A, B, C, D 중 하나를 입력하세요]

### 선택한 이유

> [여기를 지우고 그렇게 판단한 이유를 한두 문장으로 입력하세요]

### 답을 보기 전 확인

- [ ] 답을 하나 골랐습니다.
- [ ] 선택한 이유를 적었습니다.

<details color="green_bg">
<summary>실제 결과와 관점 전환 보기</summary>
	### 실제 사례
	[원문에서 확인된 결과와 중요한 수치·사례. 기사에 없는 사실을 만들지 않는다.]
	### 추천 판단
	**[선택지]**가 실제 사례의 관점 전환과 가장 가깝습니다. [왜 이 판단이 적절한지 설명]
	### 관점 전환
	**[기존에 하기 쉬운 생각]**에서 **[새롭게 볼 관점]**으로 전환합니다.
	### 내 답과 비교하기
	- 처음 판단에서 놓쳤던 정보는 무엇이었나요?
	- 실제 결과를 본 뒤 답을 바꾸고 싶다면 무엇으로 바꾸고 싶나요?
	### 다음에 가져갈 질문
	- [다른 게임이나 업무에도 적용할 수 있는 질문 1]
	- [다른 게임이나 업무에도 적용할 수 있는 질문 2]
	### 참조
	- 자료명: [원문 자료명]
	- 발행처: [회사·기관·매체]
	- 발행일: [확인된 날짜 또는 확인되지 않음]
	- 근거 수준: [공식 / 학술 / 전문 매체 / 기타 참고]
	- [원문 보기](원문 주소)
</details>
```

선택지에는 실제 사례의 관점 전환과 가까운 판단 하나와 그럴듯하지만 놓치는 점이 있는 판단들을 함께 넣는다. 추천 판단의 위치는 자료마다 바꾸고 모든 문제를 `C`로 고정하지 않는다. 정답을 맞히는 것보다 처음 판단과 실제 사례의 차이를 발견하도록 구성한다.

## Slack 요약 메시지

```text
[뉴스레터 전체 제목]

[자료 번호]. [자료의 큰 제목]

상황
[Notion 퀴즈 페이지의 상황을 1~2문장으로 작성. 추천 판단과 실제 결과는 노출하지 않음]

참조
[Notion에서 퀴즈 풀기](해당 자료의 Notion 상세 페이지 주소)

━━━━━━━━━━━━━━━━━━
```

Slack 메시지에는 `큰 제목 / 상황 / 참조`만 넣는다. `참조`에는 원문 주소 대신 해당 문제가 있는 Notion 상세 페이지 주소를 넣는다. 자료 사이에 빈 줄과 구분선을 둔다.
