# 작성 템플릿

## Notion 웹 풀이 저장 형식

웹사이트에서 사용자가 답변을 제출한 뒤 Notion에 저장할 때 아래 양식을 사용한다. 원문의 실제 결과와 추천 판단은 마지막 토글 안에만 둔다. 기사에 없는 사실은 만들지 않고, 확인할 수 없는 정보는 `확인되지 않음`으로 표시한다.

```markdown
## 상황

[원문의 결론을 미리 알려주지 않는 게임 운영·분석 상황]

## 내 답변

### 선택한 이유

**선택한 답:** [사용자가 고른 선택지와 내용]

[사용자가 입력한 선택 이유]

### 실제 답과 내 답변의 차이와 고려해볼 점

- 예상 결과: [사용자가 입력한 예상 결과]
- 가정: [사용자가 입력한 가정]
- 확신도: [사용자가 입력한 확신도]
- 잘 고려한 점: [선택한 답에서 잘 고려한 점]
- 놓친 점: [선택한 답에서 더 고려할 점]
- 결과와 별개로 합리적인 판단: [결과와 달라도 합리적일 수 있는 조건]
- 확인할 수 없는 점: [원문 근거만으로 확인할 수 없는 점]

<details color="green_bg">
<summary>실제 결과와 관점 전환 보기</summary>

	### 실제 사례

	[원문에서 확인된 결과와 중요한 수치·사례. 기사에 없는 사실을 만들지 않는다.]

	### 추천 판단

	**[선택지]**가 실제 사례의 관점 전환과 가장 가깝습니다. [왜 이 판단이 적절한지 설명]

	### 관점 전환

	**[기존에 하기 쉬운 생각]**에서 **[새롭게 볼 관점]**으로 전환합니다.

	### 내 답과 비교하기

	- 처음 판단에서 놓쳤던 정보는 무엇이었나요?
	- 실제 결과를 본 뒤 답을 바꾸고 싶다면 무엇으로 바꾸고 싶나요?

	### 다음에 가져갈 질문

	- [다른 게임이나 업무에도 적용할 수 있는 질문 1]
	- [다른 게임이나 업무에도 적용할 수 있는 질문 2]

	### 참조

	- 자료명: [원문 자료명]
	- 발행처: [회사·기관·매체]
	- 발행일: [확인된 날짜 또는 확인되지 않음]
	- 근거 수준: [공식 / 학술 / 전문 매체 / 기타 참고]
	- [원문 보기](<원문 주소>)
</details>
```

`선택한 답`, 선택 이유, 예상 결과, 가정과 확신도는 웹사이트에서 제출된 값을 그대로 사용한다. 비교 결과와 토글 안의 내용은 문제 데이터와 원문 근거에서 가져온다. 선택지에는 실제 사례의 관점 전환과 가까운 판단 하나와 그럴듯하지만 놓치는 점이 있는 판단들을 함께 넣는다. 추천 판단의 위치는 자료마다 바꾸고 모든 문제를 같은 선택지로 고정하지 않는다.

## Slack 안내 메시지

```text
YYYY-MM-DD자 사고력 키우기
http://127.0.0.1:8000
```

`YYYY-MM-DD`에는 Slack 메시지를 전송하는 날의 현지 날짜를 넣는다. 다른 요약이나 링크는 추가하지 않는다.
